LEAVES
______________________________

POST /api/leaves/request.php
Parâmetros de entrada (form-data):

tipo: enum do pedido (ex.: ferias, baixa_medica, licenca_maternidade, …) (obrigatório)

data_inicio: data YYYY-MM-DD (obrigatório)

data_fim: data YYYY-MM-DD (obrigatório)

justificacao: texto da justificação (obrigatório)

ficheiro: comprovativo (PDF/JPG/PNG ≤ 5 MB). Obrigatório para: licenca_paternidade, licenca_maternidade, baixa_medica, baixa_seguro, casamento, consulta_medica (opcional/obrigatório conforme tipo)

responsavel_id: id do substituto (opcional)

Resposta de sucesso:

ok: true

request_id: id do pedido criado

Mensagens de erro possíveis: não autenticado, role sem permissão (estrela), campos em falta, data inválida/intervalo inválido, comprovativo obrigatório, tipo de ficheiro inválido, ficheiro demasiado grande, erro ao mover ficheiro, erro de base de dados.

_______

POST /api/leaves/decision.php
Parâmetros de entrada (JSON):

pedido_id: id do pedido (obrigatório)

acao: “aprovar” | “rejeitar” (obrigatório)

comentario: motivo (obrigatório quando acao = “rejeitar”)

Resposta de sucesso:

ok: true

pedido_id: id do pedido

estado: “aprovado” | “rejeitado”

comentario: comentário (se enviado)

evento: objeto do evento criado quando aprovado (id, user_id, titulo, tipo=LEAVE, inicio, fim, status, leave_request_id) ou null

Mensagens de erro possíveis: não autenticado, role sem permissão (apenas inter2, inter, admin, adminrh, estrela), pedido inexistente, comentário obrigatório, erro de base de dados.

GET /api/leaves/aval_requests.php
(Lista de pedidos pendentes da equipa, com filtro por tipo)

type: “all” | “ferias” | “baixas” | “licencas” (opcional, default: all)

ok: true

type: filtro aplicado

items: lista de pedidos com

pedido_id

tipo, inicio, fim, justificacao

substituicao: { id, nome } ou null

comprovativo: URL ou null

pedido_em: timestamp de criação

Mensagens de erro possíveis: não autenticado, role sem permissão, erro de base de dados.

CALENDAR
______________________________
PUT /api/calendar/day_put.php
Parâmetros de entrada (JSON):

date: data no formato YYYY-MM-DD (obrigatório)

workMin: minutos de trabalho (opcional)

otMin: minutos de horas extra (opcional)

oncallMin: minutos de prevenção (opcional)

km: quilómetros percorridos (opcional)

clear: booleano, se true limpa tipos não enviados (opcional)
Resposta de sucesso:

ok: true

user_id: id do utilizador alvo

date: data marcada

updated: lista de tipos atualizados

cleared: lista de tipos limpos

status: estado dos registos (draft após gravação)
Mensagens de erro possíveis: não autenticado, role sem permissão, data inválida, período bloqueado, erro de base de dados.

________________

Parâmetros de entrada (JSON):

date: data no formato YYYY-MM-DD (obrigatório)
Resposta de sucesso:

ok: true

user_id: id do utilizador alvo

date: data limpa

deleted: número de registos apagados
Mensagens de erro possíveis: não autenticado, role sem permissão, data inválida, período bloqueado, erro de base de dados.

POST /api/calendar/batch_apply.php
Parâmetros de entrada (JSON):

start: data inicial (YYYY-MM-DD, obrigatório)

end: data final (YYYY-MM-DD, obrigatório)

workMin: minutos de trabalho a aplicar (opcional)

otMin: minutos de horas extra (opcional)

oncallMin: minutos de prevenção (opcional)

km: quilómetros percorridos (opcional)

applyWeekend: booleano, se true inclui fins de semana (default false)

overwrite: booleano, se true sobrescreve valores existentes (default true)
Resposta de sucesso:

ok: true

user_id: id do utilizador alvo

range: intervalo aplicado [start, end]

summary: totais aplicados (daysApplied, workMin, otMin, oncallMin, km)

skippedLocked: lista de dias ignorados por estarem em período bloqueado
Mensagens de erro possíveis: não autenticado, role sem permissão, intervalo inválido, nenhum campo enviado, erro de base de dados.

______

DELETE /api/calendar/batch_clear.php
Parâmetros de entrada (JSON):

start: data inicial (YYYY-MM-DD, obrigatório)

end: data final (YYYY-MM-DD, obrigatório)

applyWeekend: booleano, se true inclui fins de semana (default true)
Resposta de sucesso:

ok: true

user_id: id do utilizador alvo

range: intervalo [start, end]

deleted: número total de registos apagados

skippedLocked: lista de dias ignorados por estarem em período bloqueado
Mensagens de erro possíveis: não autenticado, role sem permissão, intervalo inválido, erro de base de dados.

________________

GET /api/calendar/get_month.php
Parâmetros de entrada:

month: mês no formato YYYY-MM (obrigatório, pode usar alternativamente date=YYYY-MM-DD)

user_id: id de outro utilizador (apenas permitido para gestores)
Resposta de sucesso:

ok: true

month: mês solicitado

period: informação do período (id, estado, start, end) ou null se não existir

days: lista de objetos por dia com

date, workMin, otMin, oncallMin, km

statuses: estado por tipo (WORK, OVERTIME, ONCALL, KM)

leaves: férias/ausências que coincidem com o dia

totals: somatório do mês (workMin, otMin, oncallMin, km)
Mensagens de erro possíveis: não autenticado, intervalo inválido, erro interno do servidor.

________________

GET /api/calendar/month_status.php
Parâmetros de entrada:

month: mês no formato YYYY-MM (obrigatório, pode usar alternativamente date=YYYY-MM-DD)

user_id: id de outro utilizador (apenas permitido para gestores)
Resposta de sucesso:

ok: true

month: mês solicitado

user_id: id do utilizador alvo

period: informação do período (id, estado, start, end, decidido_por, decidido_em, comentário) ou null

estado: estado textual do período (open, submitted, approved, rejected, locked)

flags:

canSubmit: booleano, indica se é possível submeter o mês

isLocked: booleano, indica se está bloqueado

hasDraft: booleano, indica se existem registos em rascunho

summary: totais do mês (workedDays, workMin, otMin, oncallMin, km)

range: intervalo de datas do mês
Mensagens de erro possíveis: não autenticado, intervalo inválido, erro de base de dados.

________________

POST /api/calendar/submit_month.php
Parâmetros de entrada (JSON):

month: mês no formato YYYY-MM (obrigatório, pode usar alternativamente date=YYYY-MM-DD)

user_id: id de outro utilizador (apenas permitido para gestores)
Resposta de sucesso:

ok: true

period: informação do período (id, estado=submitted, start, end)

summary: totais submetidos (workedDays, workMin, otMin, oncallMin, km)
Mensagens de erro possíveis: não autenticado, role sem permissão, mês inválido, já submetido, erro de base de dados.
